## 1. 设计目标与原则

### 1.1 设计目标

- 在**复用基线全部能力**的前提下，把红外家电遥控（FR-05）无缝接入既有系统；
- 联动链路（FR-07）依托既有 MCP 体系实现，不引入独立口令表/联动引擎；
- 新增模块可独立构建、独立验证、可回退（git 版本控制）。

### 1.2 设计原则

| 编号 | 原则 | 说明 |
|---|---|---|
| DP-1 | 复用优先 | 对话、舵机、人脸跟随、互动反馈全部复用基线；本项目代码只含「IR 模块 + MCP 扩展 + 遥控屏 + 最小板级改动」 |
| DP-2 | MCP 即联动通道 | 语音控制设备一律经 MCP 工具（`tools/call`），LLM 负责语义理解，设备侧只做能力注册 |
| DP-3 | 单一线程模型 | 沿用基线的任务/事件模型（FreeRTOS 任务 + 主循环事件），IR 服务为独立 FreeRTOS 任务，发码为短时同步操作（RMT 硬件时序，任务内阻塞） |
| DP-4 | 配置外置 | 码库、家电方位映射、GPIO 等全部配置化，不硬编码 |
| DP-5 | 可观测性 | 新增模块输出 `[IR]`/`[SERVO]` 结构化日志；摄像头暂停时序可回溯（对接 AC-4） |
| DP-6 | 最小侵入 | 对基线文件的改动最小化（预计仅 m5stack_core_s3.cc 注册 IR 服务与遥控屏入口 + CMakeLists 增源文件），其余全部为新增文件 |
| DP-7 | 离线可用 | 红外遥控屏与码库完全离线可用，不依赖云 LLM（R-8 规避） |

## 3. 核心模块设计

### 3.1 IR Driver（RMT 收发驱动）

**职责**：与硬件唯一交互点。基于 ESP-IDF RMT 外设。

```
┌──────────────┐   raw 采样序列（时长数组）   ┌──────────────┐
│ RMT TX 通道   │ ◄────────────────────────── │  IR Codec    │
│ RMT RX 通道   │ ──────────────────────────► │  协议↔时序    │
└──────────────┘   (carrier 38kHz, 由驱动配置)  └──────────────┘
```

**接口（C++）**

```cpp
namespace stackchan_ir {

class IrDriver {
public:
    struct RawSignal { std::vector<uint32_t> durations_us; bool carrier_on_first; };

    bool Init(int tx_gpio, int rx_gpio, uint32_t carrier_hz = 38000);
    bool Transmit(const RawSignal& sig);          // 阻塞至发送完成（<500ms）
    bool StartCapture(int timeout_ms);            // 异步开始接收
    bool PollCapture(RawSignal* out);             // 查询接收结果
    void StopCapture();
};

} // namespace stackchan_ir
```

**设计要点**

- 发送为**短时阻塞**（单条红外码 <1s），运行在 IR Service 任务内（DP-3）；
- 载波与空闲电平可通过组件/配置调整，兼容不同家电；
- 接收用 RMT RX 带 carrier 解调，输出时长序列供 Codec 解析。

### 3.2 IR Codec（协议编解码）

**职责**：时长序列 ↔ 家电协议码的互转。

| 协议 | 状态 | 说明 |
|---|---|---|
| NEC / NEC-ext（16/32bit） | 首期实现 | 电视/空调主流；含 repeat 帧处理 |
| Sony / RC-5 / RC-6 | 后续迭代（P2 实测覆盖后扩展） | 码库按协议+码值存储，新协议只需新增 Codec |

**接口**

```cpp
struct IrCode { std::string protocol; uint64_t data; uint16_t bits; };
std::optional<RawSignal> Encode(const IrCode& code);      // 码 → 时序
std::optional<IrCode> Decode(const RawSignal& sig);       // 时序 → 码
```

**存储格式**：码库中 `protocol + data + bits` 三要素，与驱动/时序解耦（换协议不迁移数据）。

### 3.3 IR Service（学习/发射编排）

**职责**：面向应用与 MCP 的唯一入口；管理学习流程与 Camera 暂停（RS-1）。

**状态机**

```
        ┌──────────┐
        │  IDLE    │◄────────────────────────────┐
        └──┬───────┘                             │
   emit()  │  learn_start()                       │
        ┌──▼───────┐   Capture 完成(超时/停止)   │
        │ EMITTING │   ┌────────────┐            │
        └──┬───────┘   │ LEARNING   │────────────┘
           └──────────► │            │
                        └─────┬──────┘
                              │ 捕获到信号 → Codec 解析 → 命名存储
```

**接口**

```cpp
class IrService {
public:
    struct EmitResult { bool ok; std::string error; };
    EmitResult Emit(const std::string& device, const std::string& key);
    // 学习：进入接收，timeout_ms 内捕获到即返回
    bool LearnStart(int timeout_ms);
    bool LearnPoll(IrCode* out);              // 成功返回 true，输出需命名的码
    void SetCameraPauseHook(std::function<void(bool)> hook);  // RS-1 挂钩
};
```

**RS-1 实现**：`Emit()` 内 `hook(true) → 发码 → hook(false)`，挂钩由板级注册（暂停/恢复 FaceTracker 摄像头采集）；发码失败也保证恢复（finally 语义）。

**RS-2 实现**：若当前正在 Speaking，`Emit()` 先等 TTS 播报结束（监听 `MAIN_EVENT_*` 状态）或直接执行（遥控屏离线操作不阻塞）。

### 3.4 IR Store（码库与映射持久化）

**存储**：NVS（小数据，推荐，基线已有 NVS 基础设施）或 SPIFFS JSON 文件（TBD，TC-4）；导入导出用 JSON。

```
irlib.json（SPIFFS 方案） / NVS 键值（NVS 方案）
{
  "devices": [
    { "id": "ac1", "type": "空调", "name": "客厅空调",
      "keys": { "power": {"protocol":"NEC","data":0xE0E000F0,"bits":32},
                "tempUp": {"protocol":"NEC","data":0xE0E006F9,"bits":32} } },
    { "id": "tv1", "type": "电视", "name": "客厅电视", "keys": {...} }
  ],
  "panPresets": [
    { "deviceId": "ac1", "name": "客厅空调", "yaw": 120, "pitch": 30 }
  ]
}
```

**接口**：`AddDevice / RemoveDevice / AddKey / ListDevices / GetKey / Import / Export`，全量内存缓存 + 变更即持久化。

### 3.5 IR Remote Screen（LVGL 遥控屏）

- LVGL 新页面（全屏或覆盖层，形态 TC-3 定），由触摸入口打开（如顶栏图标/手势，UI-2）；
- 结构：设备 Tab → 按键矩阵（电源/温度±/模式/风速等，按设备类型渲染）→ 学习入口；
- 交互：点击按键 = `IrService::Emit`（离线可用，DP-7）；学习中显示向导提示（UI-4）；
- 与聊天 UI 的关系：遥控屏为独立 LVGL screen，打开时聊天 UI 暂存后台，关闭恢复（状态机/Display 层管理）。

### 3.6 MCP 扩展（联动通道，FR-07 核心）

注册方式与基线 `RegisterLedMcpTools` 相同（`McpServer::AddTool`）：

| 工具 | 参数 | 说明 |
|---|---|---|
| `self.ir.send` | `device: string, key: string` | 发射指定设备按键码；未学码返回错误（携带可用设备清单，供 LLM 反馈） |
| `self.ir.learn_start` | `device: string, key: string` | **异步工具**：启动捕获（10s 超时），捕获成功/超时后由状态监听器保存并 `ReplyAsyncResult` 回传 |
| `self.ir.list` | — | 查询已学设备与按键（LLM 对话中随时可查） |
| `self.ir.delete` | `device: string, key: string?` | 删除设备（整套）或单个按键 |
| `self.servo.pan` | `yaw: int, pitch: int` | 云台转向指定方位（联动用；转向完成后自动恢复人脸跟随，RS-4） |

**异步工具机制（V1.3 新增）**：`McpTool` 支持 `async_` 标记；回调返回 `McpServer::kAsyncMarker` 时，`DoToolCall` 将调用 id 存入 `pending_async_` 队列（FIFO）不立即回复；异步动作完成后由外部调用 `McpServer::ReplyAsyncResult(result)` 回传（学习链路：`IrService` 状态监听器 → `HandleVoiceLearnCaptured/Timeout` → 保存 + 回复）。后端 MCP 客户端需容忍延迟响应（学习 ≤10s，小智服务端默认工具超时兼容）。

**联动时序（LLM 驱动）**

```
用户语音「打开客厅空调」
  → 唤醒/对话 → LLM 流式回答 且 意图=控制设备
  → tools/call self.servo.pan {yaw:120, pitch:30}     ← 先对准家电方位
  → tools/call self.ir.send {device:"ac1", key:"power"}
  → MCP 返回结果 → LLM 组织反馈语句（成功/失败）→ TTS 播报
  → 表情/LED 同步（IR 结果事件 → Avatar Display）
```

**关键点**：
- 不需要口令表：LLM 语义理解 + 工具描述（`self.ir.send` 的 description 写明可用设备/按键）；
- 失败反馈闭环：`self.ir.send` 返回错误（设备未学码/未找到）→ LLM 告知用户「请先学习 XX 遥控器」；
- 与既有 `self.camera.take_photo` 组合可实现「转头→拍照→看图」扩展（FR-02 可选增强）。

## 4. 关键机制设计

### 4.1 RS 规则实现位置（架构验证锚点）

| 规则 | 实现模块 | 验证方法 |
|---|---|---|
| RS-1 发码暂停摄像头 | IrService::Emit + 板级 Camera 挂钩 | 串口日志 `[IR] camera paused → emit done → camera resumed` 时序 |
| RS-2 不打断对话 | IrService 检查对话状态 | 对话中发码不中断 TTS |
| RS-3 屏内常驻互动 | 遥控屏不拦截 SI12T 事件 | 屏内三区摸头仍有表情反馈 |
| RS-4 转向后恢复跟随 | self.servo.pan 实现（转向→延迟→恢复 FaceTracker） | 转向完成后 ≤2s 内跟随恢复（TBD） |

### 4.2 红外学习流程（用户视角 + 内部）

**屏内学习（连续整套，离线可用）**

```
双指打开遥控屏 → 点灰色按键（或长按绿色按键重新学习）
  → IrService::LearnStart(10s) → RMT RX 捕获 → Codec 解析（重复帧忽略并延长 3s）
  → 成功：自动保存（devN 由 IrStore::GenerateDeviceId 生成，删除后不冲突）→ 按键变绿
  → 无需退出，继续点下一键 → 一台设备一套学完
  → 失败/超时：提示重试
```

**语音学习（LLM 引导，异步 MCP）**

```
用户「帮我学一下空调遥控器」
  → LLM 逐键调用 self.ir.learn_start(device="空调", key=power)
  → 板级置 ir_learn_voice_ 上下文 + LearnStart → 回调返回 kAsyncMarker（McpServer 挂起该调用）
  → 状态监听器（主线程 Schedule）：
      kCaptured → HandleVoiceLearnCaptured：LearnCapturedCode + SaveLearnedKey → ReplyAsyncResult("power 学习成功")
      kIdle(超时) → HandleVoiceLearnTimeout → ReplyAsyncResult("超时:未捕获到信号")
  → LLM 收到结果 → 语音引导下一键 / 提示重试 → 学完告知用户可语音发码
```

### 4.3 异常与降级

| 场景 | 处理 | 目标状态 |
|---|---|---|
| 发码失败（驱动超时） | 重试 1 次 → 返回错误 + 表情反馈 | IDLE |
| 摄像头暂停挂钩异常 | 发码继续，日志告警 | 不影响发射 |
| 学习超时 | 返回未捕获，提示重试 | IDLE |
| 码库损坏 | 回退空库 + 日志，可导入恢复 | 正常运行 |
| 云端不可用 | 遥控屏离线发码不受影响（DP-7） | 正常 |

## 9. 架构决策记录（ADR，V1.1 重写）

| ADR | 决策 | 备选方案 | 理由 |
|---|---|---|---|
| ADR-1 | 红外做成 MCP 工具（self.ir.*），LLM 语义直接驱动 | 自制口令表+联动引擎 | 基线 MCP 体系是现成通道（先例 self.led.*），零新增调度复杂度；语义理解由 LLM 承担更灵活 |
| ADR-2 | 红外驱动自研（RMT + NEC 首期） | 找现成 ESP-IDF 组件/旧 MOD | 无 stack-chan 生态 MOD；RMT 例程成熟、自研可控协议扩展；首期范围收敛到 NEC |
| ADR-3 | 摄像头「发码期间暂停采集」为唯一硬件级规则 | 维护完整资源仲裁器 | 基线单界面无多模式互斥；摄像头暂停窗口 <1s，简单挂钩即可（DP-6） |
| ADR-4 | 云台转向走 MCP 工具（self.servo.pan）且转向后自动恢复跟随 | 板级硬编码联动方位 | 保持 MCP 通道统一；恢复跟随避免人工干预 |
| ADR-5 | 红外码库以「协议+码值」存储，与驱动时序解耦 | 存原始时序 | 换协议不迁移数据；码库可读可迁移 |
| ADR-6 | 遥控屏离线可用，不依赖云 | 仅语音控制 | 断网仍可遥控家电（R-8 规避）；学习流程也需离线 |
| ADR-7 | 新增代码独立目录（main/ir/），基线文件改动最小化 | 散落各模块 | git 历史清晰、回退安全、评审聚焦（DP-6） |
