# 验证机编译验证说明（异地验证工作流配套文档）

> 本文档供**验证机**（具备 ESP-IDF ≥5.5 + K151 硬件）执行编译与冒烟测试使用。
> 代码在本机编写（无编译环境），所有编译错误与功能验证以本文档流程为准（计划 1.4 节 WV-1~WV-5）。

## 0. 验证机环境要求

| 项 | 要求 |
|---|---|
| ESP-IDF | **≥5.5.2**（与 `main/idf_component.yml` 的 `idf: version >=5.5.2` 一致） |
| 芯片目标 | esp32s3 |
| 网络 | 可访问 components.espressif.com（首次构建需下载 23+ 组件） |
| 硬件 | K151 整机 + USB 充电线 + 2.4G WiFi + 空调/电视及原装遥控器 |
| 串口 | USB 串口驱动（烧录用） |

## 1. 步骤一：编译基线（不含本项目代码）

> 本项目遵循仓库 `docs/code_style.md`（Google C++ 风格，根目录 `.clang-format`）。
> 每次编译前可先做风格检查（新增代码 `main/ir/` 与 `ir_remote_screen.*`）：

```bash
clang-format --dry-run --Werror main/ir/*.cc main/ir/*.h \
    main/boards/m5stack-core-s3/ir_remote_screen.cc \
    main/boards/m5stack-core-s3/ir_remote_screen.h
# 若报格式问题：clang-format -i 自动修复后再提交
```

目的：确认**上游代码本身可编译**（WV-1：区分基线问题与新增代码问题）。

```bash
git checkout 7588955            # 清理后的纯基线提交
idf.py set-target esp32s3       # 若未配置过
idf.py build                    # 或 python ./scripts/release.py m5stack-core-s3
```

**预期**：编译成功，产物 `build/xiaozhi.bin`。若此处失败 → 环境问题，先解决环境再继续。

**烧录基线验证**（可选但推荐）：

```bash
idf.py -p COM端口 flash
```

开机验证：唤醒「土豆土豆」→ 对话、触摸互动、人脸跟随正常。（对照 [开发计划.md](开发计划.md) P1.3 的基线验证项）

## 2. 步骤二：编译本项目代码（当前 HEAD）

```bash
git checkout master             # 或最新提交（含 IR 模块 + 板级集成 + 遥控屏）
idf.py build
```

**预期**：编译成功。失败时按下文第 5 节处理。

## 3. 步骤三：烧录与冒烟测试

```bash
idf.py -p COM端口 flash && idf.py -p COM端口 monitor
```

### 3.1 启动日志检查（开机后串口）

| 日志 | 含义 |
|---|---|
| `IR.Service Attached: driver=ok store=ok` | IR 服务装配成功 |
| `IR service ready (tx=GPIO.. rx=GPIO..)` | IR 驱动初始化成功 |
| `IR driver init failed ... GPIO not configured (TC-8)` | ⚠️ 未配置红外引脚（见第 4 节） |
| `IR remote screen ready` | 遥控屏就绪 |

### 3.2 冒烟用例（逐条执行并记录）

| # | 用例 | 操作 | 预期 |
|---|---|---|---|
| 1 | 基线回归 | 唤醒「土豆土豆」→ 对话、摸头、摇晃 | 与未加代码前行为一致 |
| 2 | 打开遥控屏 | **双指同时触摸屏幕** | 进入「红外遥控」界面，返回按钮在左上角 |
| 3 | 遥控屏内互动 | 屏内三区摸头 | 仍有爱心表情/语料反馈（RS-3） |
| 4 | 学习空调 | 新设备 → 点「电源」→ 对准空调遥控器按电源键 | 状态显示「已保存 power」，按键变绿 |
| 5 | 回放发射 | 点绿色「电源」键 | 日志 `[IR.Service] state -> 1 (..) → emitted`；空调动作 |
| 6 | 摄像头暂停时序 | 发射时观察串口 | `[IR] camera paused → emit done → camera resumed`（RS-1） |
| 7 | 学习电视 | 重复用例 4（电视遥控器） | 同 4/5 |
| 8 | 码库持久化 | 学习后重启设备 | 遥控屏设备仍在，按键仍为绿色 |
| 9 | 语音联动 | 「打开客厅空调」（先在 xiaozhi 后台确认 LLM 工具可用） | 云台转向 → 发码 → TTS 反馈（FR-07） |
| 10 | 云台转向 | 语音「看右边」类指令或直接验证 | 转向后 2s 恢复人脸跟随（RS-4，日志 `pan_restore`） |
| 11 | 双指返回 | 遥控屏列表页点「返回」 | 回到聊天界面 |
| 12 | 连续压力 | 连续点击发射 30 次 | 无死机、无卡死（NFR-2） |

## 4. 红外 GPIO 引脚（TC-8 已闭环）

已按 M5Stack 官方 StackChan(K151) 文档引脚表配置（`main/ir/ir_config.h`）：
**G5 = IR_SEND（发射），G10 = IR_REC（接收）**。
同表 Servo_TX=G6/Servo_RX=G7、I2C SDA=G12/SCL=G11 与板代码完全一致（交叉验证通过）。
若冒烟用例 4/5（学习/回放）异常，优先复核这两处引脚定义（来源：
docs.m5stack.com/zh_CN/StackChan）。

## 5. 常见编译问题与处理（按出现概率排序）

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | `rmt_*` 符号未找到 / `esp_driver_rmt` 相关错误 | PRIV_REQUIRES 缺 `esp_driver_rmt` | 已加入 `main/CMakeLists.txt`；若仍报错检查 IDF 版本 |
| 2 | `lv_indev_create`/`lv_indev_set_read_cb` 不存在 | LVGL 版本 API 差异（本项目 lvgl 9.5） | 若编译器报此错误，把 [ir_remote_screen.cc](../main/boards/m5stack-core-s3/ir_remote_screen.cc) `BuildUi` 末尾的 indev 创建改为旧 API：`lv_indev_drv_init(&drv); drv.type=LV_INDEV_TYPE_POINTER; drv.read_cb=IndevReadCb; lv_indev_drv_register(&drv);`（把 `drv` 存为成员或 static） |
| 3 | `rmt_carrier_config_t` 字段（duty_cycle）报错 | IDF 5.5 之前版本无此字段 | 删除 `.duty_cycle = ...` 行（默认 50% 载波仍可用）；或升级 IDF |
| 4 | 编译通过但 `IR driver init failed` | 引脚未配置（TC-8） | 见第 4 节 |
| 5 | 编译通过但遥控屏无响应 | indev 未生效 / 触摸坐标方向不对 | 见 5.1 |

### 5.1 遥控屏触摸无响应排查

1. 确认开机日志有 `IR remote screen ready`；
2. 双指触摸后日志有 `[IR.Screen] Opened` → 屏已打开；
3. 触摸屏坐标方向：若按钮点击错位（点 A 触发 B），说明 FT6336 坐标与屏幕方向不一致。修改 [m5stack_core_s3.cc](../main/boards/m5stack-core-s3/m5stack_core_s3.cc) `InitializeIrRemoteScreen` 的读回调，对 x/y 做镜像/旋转（参考 `DISPLAY_MIRROR_*` 配置，320x240）；
4. 若点击完全无反应：检查 indev 回调是否被调用（LVGL 9 的 `lv_indev_set_read_cb` 正确性），必要时按上表第 2 项换 API。
