# 研究报告：主动推送消息给 StackChan 的可行通道

> 2026-08-07 | 研究性质：代码全链路核实（协议文档 + application.cc + MQTT + HTTP）
> 结论：**通道存在且部分现成**——MQTT 模式 Idle 常连，服务器随时可推 JSON。

## 1. 结论速览

| # | 通道 | 现状 | 改动量 |
|---|---|---|---|
| 1 | MQTT 常连 + `alert` 消息 | ✅ **现成**：Idle 时 MQTT 常连；`alert` 无条件执行（上屏 + 本地提示音 + 表情，application.cc:611-619）——服务器推一条 JSON 设备即有反应 | **0** |
| 2 | MQTT + `mcp tools/call` | ✅ **现成**：Idle 无状态 gate（application.cc:593-597）——服务器可直接调用设备全部工具（表情/舵机/灯/红外/拍照…） | **0** |
| 3 | MQTT + `tts`（主动说话） | ⚠️ **部分现成**：此前对话过（UDP 音频通道仍开）则推 `tts start` + 音频帧直接播报；**冷启动后从未对话则「假 Speaking」无声** | **小**（一行：`tts start` 分支检测通道未开自动 `OpenAudioChannel()`） |
| 4 | `custom` 消息（RECEIVE_CUSTOM_MESSAGE） | ⚠️ 仅「打日志 + 上屏显示」（application.cc:620-631），不是命令通道——要用需自己加业务代码 | 中 |
| 5 | `listen`（命令设备开麦） | ❌ **协议不支持**（无此下行分支，收到落「Unknown message」） | — |
| 6 | 局域网直连（设备 HTTP server） | ✅ 可行：固件无 HTTP server（净新增 esp_http_server，IDF 内置）；**离线方案**：POST `{"action":"speak","file":"xxx.ogg"}` → 播放 SD 卡预置音频（复用音乐管线）——不依赖云端 | 中 |

## 2. 关键机制

- **MQTT 是默认模式且 Idle 常连**（mqtt_protocol.cc:55-57；断线仅 Idle 自动重连）——服务器随时可推 JSON 控制面
- **UDP 音频通道是命门**：JSON 走 MQTT 常连，**音频帧走 UDP**，只在 `OpenAudioChannel()`（hello 交换）时创建（mqtt_protocol.cc:215-239）；会话结束**不关通道**（仅手动停止/断网/重启才关，application.cc:736-738）——「此前对话过」是推送说话能否出声音的分水岭
- **音频帧有状态 gate**：仅 Speaking 状态才入解码队列（application.cc:526-530），Idle 收到的音频被静默丢弃
- **WebSocket 模式不可行**：Idle 无常连（websocket_protocol.cc:23-26）
- **文本→声音只能在服务器侧合成 TTS**：设备无本地 TTS 引擎；「推文本让它说话」无现成路径（播 SD 预置音频除外）
- **`alert` 是文档缺口**：能触发「动作+提示音+表情」但未写入 websocket_zh.md，以代码为准

## 3. 推荐实施路径（按需取用）

1. **固件一行修复**：`tts start` 分支（application.cc:552-558）检测 `IsAudioChannelOpened()==false` 时先 `OpenAudioChannel()`——让推送说话 100% 可靠
2. **服务器端推送**（自建 xiaozhi 服务器）：`alert` 消息（零改动）→ 扩展 TTS 推送（服务器合成 → `tts start` + UDP 音频帧）
3. **局域网直连**：设备新增 esp_http_server + POST 端点 → 播 SD 音频 / 表情 / 舵机动作（离线可用）
4. **可选**：`custom` 消息扩展为动作命令（把「上屏」升级为「执行动作」，如 payload 里带 `action` 字段）

## 4. 待确认风险

- 服务器 → 设备的 MQTT **下行 topic 结构在外部组件**（78/esp-wifi-connect，构建期拉取），本仓不可验证——服务器端推送前需实测确认 publish 路径
- `alert` 行为以代码为准（无文档佐证）
- 推送说话依赖此前开过 UDP 通道（见第 2 节），冷启动场景需先应用「一行修复」
