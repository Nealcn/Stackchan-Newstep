## 2. 项目概述

### 2.1 背景

持有**官方成品 StackChan（K151 单机整机）**一台（ESP32-S3 + 摄像头 GC0308 + 双轴舵机云台 + BMI270 IMU + 三区触控 + FT6336 触摸屏 + 红外收发 + NFC + 麦克风/扬声器 + WiFi/蓝牙 + 锂电池 + WS2812 LED×12）。

基线与原始规划预期不同：经源码实证（[基线盘点与清理分析.md](基线盘点与清理分析.md)），Nealcn/stackchan-neal 是 **xiaozhi-esp32 v2.2.6（小智 AI 机器人）的深度定制分支**——K151 的舵机云台、人脸跟随、三区摸头、摇晃/抱起检测、程序化表情、情绪 LED 已全部实现并常驻运行；AI 语音对话为固件核心（离线唤醒「土豆土豆」+ 小智云端流式 ASR/LLM/TTS）；摄像头双用途（人脸跟随 + MCP 拍照问答）。**缺失部分仅为：红外家电遥控（无任何红外代码）。**

因此本项目从「5 项原生功能融合调度」调整为：**以既有小智对话 + StackChan 互动为底座，新增红外家电遥控能力，并打通「语音 → 云台 → 红外 → 表情」的 MCP 联动链路**。

### 2.2 项目目标

- G1：在零外接硬件、无本地大模型约束下，将红外家电遥控新增并完整融合进既有系统；
- G2：依托既有单界面交互（语音/触摸/表情），形成「对话 + 互动 + 遥控」一体的使用体验，不新增多页面切换复杂度；
- G3：硬件级资源规则正确（红外发码时暂停摄像头采集等），常驻互动（摸头/摇晃/人脸跟随）全程不受影响；
- G4：打通语音 → 云台 → 红外 → 表情的联动闭环（LLM 语义直接驱动，无需口令表）；
- G5：形成固化最终固件 + 操作手册，交付即用。

### 2.3 项目边界（范围外声明）

| 编号 | 范围外项 | 说明 |
|---|---|---|
| EX-1 | 新增外设硬件 | 不添加轮子底盘、腿部、外置电池、本地算力设备等任何外设 |
| EX-2 | 本地部署大模型 | 不部署本地大模型；AI 能力全部走小智云端（xiaozhi.me 或自建服务器） |
| EX-3 | 改装内置硬件 | 不改装内部电池、不更换原装元器件 |
| EX-4 | 真人动作复刻 | 基线无此功能（官方 stack-chan 生态才具备）；本项目不开发姿态估计/动作复刻 |
| EX-5 | 手机远程视频监控/推流 | 不做 H.264 推流与手机监控端；摄像头能力维持「人脸跟随 + 拍照问答」 |
| EX-6 | 首页滑动多页面 UI | 基线为单屏聊天界面，不做 4 页面滑动容器改造（V1.0 此需求取消，见 C-3 修订） |
| EX-7 | 底层重写 | 不重写音频/显示/舵机等核心驱动；开发以「新增模块 + MCP 工具 + 少量板级改动」为主 |

### 2.4 总体约束清单

| 编号 | 约束 | 说明 |
|---|---|---|
| C-1 | 供电仅使用原装电池 + USB 充电宝补电 | 不改装内部电池、不外接底座大容量电池 |

**核心设计原则（V1.1）**

1. **复用优先**：对话链路、舵机、人脸跟随、互动反馈全部复用基线，不重复实现；
2. **MCP 即联动通道**：语音控制红外 = LLM 语义理解 → `tools/call self.ir.*`，无需自制口令表与联动引擎；
3. **单一硬件级规则**：本项目唯一硬性资源规则是「红外发码期间暂停摄像头采集」（无多模式互斥问题）；
4. **配置外置**：红外码库、家电-云台方位映射以文件/配置形式存储，不硬编码；
5. **可观测性**：新增模块输出结构化日志（`[IR]` 前缀），联动与学习流程可回溯。

## 4. 功能需求

优先级：**P0** = 核心，缺一不可；**P1** = 重要；**P2** = 增强。
标有 (TBD) 的量化指标，需实测后固化。

### 4.1 FR-01 表情对话与摄像头跟随（P0，复用基线）

**描述**（V1.1 修订，替代原「Avatar 真人动作复刻」）
- 程序化 LVGL Avatar（约 21 种表情、眨眼、呼吸、说话嘴型）随对话状态与情绪实时变化；
- 摄像头 + 云台人脸/动作跟随常驻：目标移动时云台平滑跟踪（yaw±45°/pitch 5-60°），对话进行中自动暂停、结束恢复；
- 待机时云台随机扫视，点头/摇头/歪头动画随表情联动。

**验收标准**
- 开机即呈现 Avatar 表情，说话/聆听/待机状态表情正确切换；
- 摄像头前方有人移动时云台跟随、无卡死；对话期间暂停跟随、结束后恢复；
- 表情联动舵机动画（点头/摇头/歪头）正常。

### 4.2 FR-02 拍照问答能力（P1，复用基线，可选增强）

**描述**（V1.1 修订，替代原「云台监控摄像头模式」）
- 复用既有 MCP 工具 `self.camera.take_photo`：LLM 对话中按需拍照并看图问答；
- 可选增强：配合云台转向工具（FR-07）实现「转头看指定方向 → 拍照 → 问答」。

**验收标准**
- 对话中指令拍照（如「看看我在干嘛」）返回图像理解结果；
- 拍照期间与其他服务（舵机跟随、红外）无冲突。

### 4.3 FR-03 触控 + 姿态趣味互动（P0，复用基线，已实现）

**描述**
- 三区摸头（SI12T）、触摸屏手势（单击/双击/滑动/长按摸头）、摇晃/抱起（BMI270）→ 随机语料 + 表情 + 舵机动画 + LED 反馈；
- 常驻所有对话状态生效。

**验收标准**
- 全部手势与姿态触发各自反馈闭环，5s 冷却（触摸）/5min 冷却（IMU）机制符合基线行为；
- 新增红外功能后互动不受影响（回归验证）。

### 4.4 FR-04 联网云端 AI 语音助手（P0，复用基线）

**描述**
- 离线唤醒词「土豆土豆」→ 小智云端流式 ASR/LLM/TTS 对话，支持语音打断；
- 配网（热点方式）、OTA 升级、低电提醒沿用基线。

**验收标准**
- 唤醒-对话-播报闭环可用；断网重连正常；
- LLM 可调用 MCP 工具（含新增红外工具）完成设备控制。

### 4.5 FR-05 红外家电遥控（P0，本项目新增核心）

**描述**（V1.1 重写：无社区 MOD 可刷，采用 ESP-IDF 原生方案）
- **驱动**：基于 ESP-IDF RMT 外设实现红外收发驱动（支持 NEC 等主流家电编码协议，协议集以实测覆盖为准）；
- **学习**：进入学习模式 → 对准原装遥控器接收编码 → 命名存储 → 回放测试（支持空调、电视等至少 2 类家电）；
- **码库**：持久化存储（设备-按键-编码），重启不丢失，支持增删改查与导入导出；
- **发射**：按设备+按键发射红外码；
- **入口**：① 语音（LLM 经 MCP 工具 `self.ir.send`）；② 触摸（新增 LVGL 红外遥控屏：设备列表 + 按键矩阵，点击发码）。

**验收标准**
- 空调、电视两类家电完成学习-回放闭环（学习成功后可稳定触发 3 次以上）；
- 码库重启后仍在；遥控屏可完成单键与组合操作；
- 红外发射期间摄像头采集临时暂停、发码后恢复（FR-06）；
- 发射距离 ≥3m 内可靠触发（TBD 实测）。

### 4.6 FR-06 硬件资源管理（P0，本项目集成层）

**描述**（V1.1 修订，替代原「模式切换与资源调度」；基线无多模式互斥问题，仅保留硬件级规则）

| 规则编号 | 场景 | 行为 |
|---|---|---|
| RS-1 | 红外发射中 | 临时暂停摄像头采集（降电磁干扰），发码完成恢复（人脸跟随同步暂停） |
| RS-2 | 红外学习/发射与对话 | 互不阻塞：发码或学习时若在对话，TTS 播报完成后再执行（不打断） |
| RS-3 | 红外遥控屏打开 | 常驻互动（触摸/摇晃）在屏内保持可用，三区摸头不冲突 |
| RS-4 | 云台转向（联动） | 云台转向指令与人脸跟随抢占：联动转向完成后恢复跟随（跟随让位时间 ≤2s，TBD） |

**验收标准**
- 发码瞬间串口日志确认 `camera paused → emit → resumed` 时序；
- 遥控屏操作与常驻互动无冲突；
- 连续 30 次发码无死机、无卡死（TBD 次数）。

### 4.7 FR-07 「语音 → 云台 → 红外 → 表情」联动链路（P1，MCP 方案）

**描述**（V1.1 重写：由「口令表+联动引擎」改为 MCP 工具方案）
- 新增 MCP 工具：`self.ir.send(device, key)`、`self.ir.learn(...)`、`self.servo.pan(yaw, pitch)`（云台转向）；
- 动作/表情工具（源自 stackchan-mcp 引入评估，V1.2 补充）：`self.servo.nod`（点头）/`self.servo.shake`（摇头）/`self.servo.home`（归位，2s 后恢复跟随）/`self.face.set_emotion`（21 种表情，自动联动舵机动画与情绪灯）；
- 用户语音指令（如「打开客厅空调」）→ LLM 语义理解 → 依次调用 `self.servo.pan`（转向家电方位预设）→ `self.ir.send` → 表情/LED 反馈执行结果；
- 家电方位-云台角度映射以配置维护（遥控屏校准或语音配置）。

**验收标准**
- 至少 3 条自然语言指令（如「开空调」「关电视」「空调制冷25度」）端到端执行成功；
- 链路时序：转向 → 发码 → 表情反馈，全程 ≤8s (TBD，含语音识别与 LLM 推理)；
- 执行失败（未学到该码/设备未学码）有明确语音+表情反馈。

### 4.8 FR-08 表情/LED 反馈（P2，增强）

**描述**：红外执行结果（发码成功/失败、学习完成）与设备状态在表情屏与 LED 上有明确反馈；扩展既有表情映射。

**验收标准**：发码成功/失败/学习中三种状态均有可区分反馈。

## 8. 数据与配置需求（V1.1 调整）

### 8.1 红外码库（DAT-1）

- 结构：`设备类型（空调/电视/…）→ 设备名称 → 按键 → 红外编码（协议+码值）`；
- 持久化存储（NVS 或 SPIFFS 文件，P3 定），支持增删改查、导入导出；
- 支持多键位（电源/温度±/模式/风速等）。

### 8.2 家电方位-联动映射表（DAT-2）

- 结构：`家电名称 → 云台方位预设（yaw/pitch）→ 关联设备与按键`；
- 供 LLM 联动参考：`self.servo.pan` 的方位参数与 `self.ir.send` 的按键参数；
- 配置入口（V1.2 已定）：语音方式——用户说「记下空调的位置」→ LLM 调 `self.servo.pan(device=ac1, yaw, pitch)` → 持久化到码库 JSON；`self.ir.send` 工具描述动态携带各设备方位，联动时 LLM 直接引用。

### 8.3 系统配置（DAT-3）

- 沿用基线 NVS 配置体系（WiFi、OTA、服务器地址）；
- 新增：红外发射 GPIO、码库存储路径、联动默认方位等，以配置文件集中管理。
